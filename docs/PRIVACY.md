# Privacy — every data flow

This file is a promise. If the code ever does something that isn't listed here, that's a bug.
Any change that adds or changes a data flow or permission must update this file in the same change
(AGENTS.md rule 4).

## Short version

- **Pairline has no servers in version 1.** Nothing about you is sent to us.
- **Your data moves only between your two phones.** Messages, contacts, call history and call audio go
  directly between them, encrypted.
- **Only two outside companies are involved, and neither gets your data:** Apple, when you buy something in the
  iPhone app, and GitHub, which the Android app asks once a day whether a new version exists (you can turn that off).

## Data flows

| Data | Leaves the device? | Goes to | Stored where | How long |
|------|--------------------|---------|--------------|----------|
| SMS (text, numbers, time) | Yes, encrypted | Your paired iPhone only | Android's own SMS store, as usual; on iPhone, Pairline's local database | Until you delete it or unpair. Deleting on the iPhone removes it there only: Android lets only its default messaging app delete texts |
| Contacts | Yes, encrypted | Your paired iPhone only | iPhone: local cache | Until unpair |
| Call log | Yes, encrypted | Your paired iPhone only | iPhone: local cache | Until you delete it or unpair. Deleting on the iPhone also deletes it on the bridge phone when Pairline Bridge has the call-history permission |
| Block list (numbers and sender names you block) | Yes, encrypted | Between your two phones only | Bridge app's private storage (excluded from backups); iPhone: Pairline's local database | Until you unblock them; unpairing removes the iPhone's copy (D-043) |
| Contacts you add on the iPhone (opt-in, off until you turn it on in the bridge app) | Yes, encrypted | Your bridge phone only | Android Contacts | Until you delete them |
| Files you send (M5), only when you share them | Yes, encrypted, over the local Wi-Fi link only | The other paired phone only | Android: Downloads/Pairline (Android 10+) or Pairline's own folder (Android 9). iPhone: Pairline's Received folder, visible in the Files app | Until you delete them |
| The bridge's local Wi-Fi addresses and Wi-Fi port (M5) | Yes: in the pairing QR code, and encrypted to your paired iPhone (`wifi.offer`) | Your iPhone only | iPhone: with the pairing, to reconnect | Until unpair |
| That a Pairline bridge is on this Wi-Fi network (M5, DNS-SD `_pairline._tcp`) | Yes, announced to devices on the same local network | Devices on your Wi-Fi network can see a service with a random name that changes every time the link starts. No phone name, number, model or device id | Not stored | While the Wi-Fi link is on |
| Hotspot name and passphrase, only while you run Pairline's own hotspot ("Hotspot for iPhone") on the bridge (M5) | Yes: in the pairing QR code, and encrypted to your paired iPhone | Your iPhone only, which asks you before joining | Generated by Android for each hotspot; the bridge keeps it in memory only. iPhone: with the pairing in the Keychain (this device only), and iOS keeps a joined network in its Wi-Fi settings until the bridge stops offering it or you unpair; Pairline then removes the networks it added (D-061) | Bridge: until the hotspot stops. iPhone: until unpair, or until you forget the network in iOS |
| Your iPhone's internet traffic, only while internet sharing is on (M8) | Yes | Through your bridge phone (and its VPN, if one is on) to the sites your iPhone visits. Off until you allow it in the bridge app; then the iPhone turns it on and off. Sites you choose to send direct (e.g. `.ir`) skip the bridge | Not stored, not logged (the log keeps only how many connections were served) | — |
| Proxy credentials for internet sharing (M8) | Yes, encrypted | Your paired iPhone only | Bridge app storage; kept from one start to the next so the iPhone's proxy settings keep working (D-058) | Until you switch internet sharing off in the bridge app |
| The current Wi-Fi's proxy setting (iPhone) | No | Read on the iPhone only, to say whether it points at the bridge's internet sharing | Not stored | — |
| Call events (who's calling) | Yes, encrypted | Your paired iPhone only | iPhone Recents only if you turn that setting on (Recents can sync to iCloud) | Per iOS settings |
| Call audio, only with "Talk on iPhone" on and only during a call you take on the iPhone (M6) | Yes, encrypted | Streamed live between your two phones over your local Wi-Fi: the caller's voice to the iPhone, your iPhone's microphone into the call | Not stored, not recorded; logs keep only frame counts and loudness levels | — |
| Wireless debugging pairing (Talk on iPhone, D-054) | No. Pairline connects only to this phone's own Wireless debugging, on 127.0.0.1; to find its port it looks for this phone's own `_adb-tls-*` announcements on the Wi-Fi network (mDNS), which every phone with Wireless debugging on sends anyway | Pairline's 2048-bit key in Pairline's no-backup storage, encrypted with an Android Keystore key; Android keeps the matching public key under Wireless debugging › Paired devices, named "Pairline". The 6-digit code you type goes only into that pairing and isn't stored | Until "Forget pairing" (and removing Pairline under Paired devices) |
| USSD results | Yes, encrypted | Your paired iPhone only | Not stored | — |
| Phone status (battery, signal, carrier, which SIM Android uses for calls and for texts, your SIM numbers if Android knows them) | Yes, encrypted | Your paired iPhone only | Not stored | — |
| Device model and system version (`device.info`: e.g. "Google Pixel 7", Android 16, app version; on the iPhone side the generic model "iPhone") | Yes, encrypted | The other paired phone only | Bridge app settings: the iPhone's model and iOS/app version, to show them on screen | Until unpair |
| Pairing keys | No | — | Android Keystore-protected storage; iOS Secure Enclave or Keychain | Until unpair |
| Pairing code (the QR code's one-time secret) | Only as the QR code on your screen | — | Bridge app memory only, never on disk or in logs | 5 minutes, or until used once |
| SMS on the bridge | — | — | Pairline keeps no copy: it reads Android's own SMS store when the iPhone asks, and Android stores messages sent from the iPhone in its Sent box as usual | — |
| Purchases | Yes | Apple (App Store) | Apple | Apple's policy. Pairline only checks Apple-signed transactions on the device |
| App logs, including a crash's code locations | Only if you choose to share them | Wherever you send them | On the device, last 7 days, readable by you | Rolling |
| Backups of the Android app's data | No | — | The Android app opts out of Google cloud backup and of copying to a new phone | — |

### On the iPhone

| Data | Leaves the iPhone? | Stored where | How long |
|------|--------------------|--------------|----------|
| Synced SMS, contacts and call log | No | Pairline's SQLite database in the app's Application Support folder, file protection `completeUntilFirstUserAuthentication` (readable after the first unlock, so messages that arrive while locked can be saved), **excluded from iCloud and computer backups** | Until unpair (unpairing deletes it) |
| Messages you write before the bridge confirms them | Yes, encrypted, to your bridge phone only | Same database (an outbox), sent when the link is up | Until sent; then like any message |
| What you deleted (so a later sync doesn't bring it back) | No | Same database: the deleted message's or call's id and time, and for a deleted conversation its id and the other party's number. Never the text (D-043) | Until unpair |
| Block list | Yes, encrypted, to your bridge phone only (it keeps the list that counts) | Same database, a copy of the bridge's list | Until you unblock or unpair |
| New-message and code notifications | No (iOS may mirror notifications to your own Apple Watch) | iOS Notification Center. Sender name or number and, if "Show message text" is on, the text | Until you clear them; unpairing clears them |
| Incoming-call notification (only when iOS doesn't show the call screen, e.g. Focus) | No (iOS may mirror notifications to your own Apple Watch) | iOS Notification Center. The caller's name or number | Removed when the call ends |
| One-time codes | No | Detected on the iPhone only. "Copy code" puts the code on **this iPhone's** clipboard: never on Universal Clipboard, and it expires after 3 minutes. Other copied text is also local-only | 3 minutes |
| Widget status (link state, bridge battery, signal, carrier name) | No | The app group container shared with Pairline's own widget. No messages, numbers or contacts | Overwritten on every status update; deleted on unpair |
| Lock Screen / Dynamic Island status (Live Activity, D-053): link state, bridge name, battery, each SIM's carrier, network type and signal | No. Started and updated on the iPhone only; Pairline has no push server, so nothing goes through Apple's push service | iOS shows it on the Lock Screen and in the Dynamic Island while Settings › "Bridge status on Lock Screen" is on (the default). No messages, numbers or contacts | Ended when you turn the setting off or unpair; iOS ends it after 8 hours at most |
| Identity key and pinned bridge key | No | Secure Enclave key (or Keychain key on devices without one) and Keychain items, `AfterFirstUnlockThisDeviceOnly`, never synced or migrated | Until unpair (the bridge key) / app removal (the identity key) |
| Trial clock | No | The latest trusted time seen (D-017), in the Keychain, so turning the clock back doesn't extend the trial | Until app removal |
| Free first sync used | No | One flag in the Keychain (D-069), so pairing again doesn't give a second free sync. No content | Like the trial clock |
| Preferences (including the SIM for new calls and messages, D-062) and saved USSD codes | No | iOS user defaults (no message content) | Until app removal |
| Demo mode data | No | Made-up sample data in memory only, never mixed with real data | Until you leave demo mode |
| App logs | Only if you tap Share after reading them | Application Support, redacted (no phone numbers, emails, device ids or message text) | Last 7 days |
| Pairing link (QR code) | No | Read from the camera and used once; the secret is never stored or logged | Until pairing ends |

## Network connections

| App | Connects to | Why |
|-----|-------------|-----|
| Android bridge | Your iPhone over Bluetooth LE | The link |
| Android bridge, unless you turn the Wi-Fi link off | Your iPhone over local Wi-Fi: listens on TCP port 47820 (and a UDP port for call audio) only on its Wi-Fi and hotspot addresses, never on mobile data or VPNs, and refuses anything that isn't on your local network. Announces itself with DNS-SD (random name) | The Wi-Fi link (M5): the same encrypted session as Bluetooth, plus call audio and files |
| Android bridge, unless you turn it off | `api.github.com` once a day, and GitHub's download servers when you tap Update | Checks for a newer Pairline Bridge release. The request carries no user data; GitHub sees your IP address and that a Pairline app asked (D-041). The downloaded APK stays in the app's private cache until Android has it, and is installed only after you confirm on Android's screen (D-042) |
| iPhone app | Your bridge phone over Bluetooth LE and local Wi-Fi | The link |
| iPhone app | Apple App Store (StoreKit) | Purchases |
| Android bridge, only while internet sharing is on (M8) | The sites your iPhone visits | Forwards your iPhone's own traffic; Pairline starts no connections of its own |
| Android bridge, only with Talk on iPhone | This phone's own Wireless debugging on `127.0.0.1`; its port is found from this phone's own `_adb-tls-*` announcements on the Wi-Fi network | Pairs with it once and starts Pairline's helper (D-054). Never connects to another device's Wireless debugging |

Nothing else. The Android app's network code is confined by CI to four places: the update check (GitHub only),
the Wi-Fi link (addresses on your local network only), internet sharing (M8, only while you have it on) and Talk on
iPhone's connection to this phone's own Wireless debugging (`127.0.0.1` only).
**Debug builds only** (never the release APK): the bridge also listens on `127.0.0.1:47800` inside the phone or
emulator, so developers can connect a test iPhone app through `adb forward` (D-018); it isn't reachable from any
network. On an emulator (never on a phone), a debug build's Wi-Fi link also listens on the emulator's emulated
mobile-data interface, the only one the Mac can reach through `adb emu redir`. Debug builds also copy each log line,
already redacted, to Android's logcat, which a connected computer can read. Setup videos, routing lists and the
known-device list ship inside the app, so nothing else is downloaded.
Links you tap in Settings (the source code, Pairline's Telegram news channel and help group for your language) are
handed to your browser or the Telegram app; the bridge doesn't open them itself.

**iPhone app:** it makes no network requests of its own; the only outside party is Apple (StoreKit, App Store
purchases and restores). Links you tap — the bridge download page `getpairline.com`, the privacy policy, the terms,
the source code, Pairline's Telegram news channel and help group (`t.me`, for the app's language), or a link inside a
message — open in Safari or the Telegram app, only when you tap them. The Telegram help group is public, and the app
says so next to the link. **Debug builds only** (never
release builds, checked by CI with `ios-policy-check.sh`): the app can connect to a test bridge on `127.0.0.1`
(loopback, D-018) instead of Bluetooth, can pair from a `pairline://pair` link instead of the camera, and copies each
log line, already redacted, to the iPhone's system log, which a connected Mac can read.

| `POST_NOTIFICATIONS` (Android 13+) | The status notification the background service requires | Setup |

| `INTERNET` | The Wi-Fi link (local addresses only), the daily update check against GitHub, which you can turn off (D-041), and Talk on iPhone's connection to this phone's own Wireless debugging on 127.0.0.1 (D-054) | Install |
| `REQUEST_INSTALL_PACKAGES` | Hand a downloaded update, after its checksum and signature are checked, to Android's own installer, which asks you to confirm every update (D-042). Android also asks you once to allow "Install unknown apps" for Pairline | When you first tap Update |
| `INTERNET` (**debug builds only**) | The local test transport on `127.0.0.1:47800` (D-018) | Install |
| `CHANGE_NETWORK_STATE` (**debug builds only**) | On the Android emulator only, the Wi-Fi link is reached through the emulator's own NAT on its emulated mobile-data interface; this lets the call-audio socket answer on that interface (D-044) | Install |

It changes no other setting. Turning Talk on iPhone off, or "Forget pairing", returns the permission | Granted once the helper first runs |
| Notifications: pairing code (optional) | During pairing only: a notification you type the 6-digit Wireless debugging code into | While pairing |

## Things Pairline will never do

- Upload your messages, contacts, call history, audio or files to any server.
- Include analytics, advertising or tracking code.
- Look up your IP address or location with third-party services.
- Download routing lists, device lists or anything else from third-party sites.
- Install updates without asking you.
- Change a system setting you didn't ask for. The one exception is Talk on iPhone: once you've set it up, and only while it's on, Pairline turns Developer options, USB debugging and Wireless debugging back on when its helper needs them; turning Talk on iPhone off, or "Forget pairing", ends that.
